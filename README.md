# AI Code Review Playbook & Evaluation Rubric

[![Code Review](https://img.shields.io/badge/Focus-AI_Code_Audit-purple.svg)]()
[![Security](https://img.shields.io/badge/Focus-AppSec-red.svg)]()

A practical framework for auditing AI-generated code. This repository is not a software tool; it is a **methodology** and a set of **self-audit artifacts** used to systematically evaluate the quality, security, and concurrency of code generated by Large Language Models (LLMs).

## Executive Summary
AI models are excellent at generating code that "works" in the happy path, but they frequently hallucinate safety and performance. They often introduce subtle race conditions, SQL injections, and memory leaks. 

To evaluate AI code at a Senior/Staff level, you cannot just "run the tests." You need a strict rubric. This playbook provides the exact criteria, examples of vulnerabilities, and actionable code reviews used to train and evaluate AI models in high-stakes environments.

## What's inside?
1. **`REVIEW_RUBRIC.md`:** A strict 4-pillar checklist for every code review:
   - Security (SQLi, Command Injection, Secrets).
   - Concurrency (Race conditions, Locks, Deadlocks).
   - Performance (N+1 queries, Memory leaks).
   - Correctness (Edge cases, Exception handling).
2. **`bad_code_examples/`:** Real examples of vulnerable code commonly produced by LLMs.
   - `race_condition.py`: A classic Read-Modify-Write bug.
   - `security_flaws.py`: Unparameterized SQL and shell injections.
3. **`my_reviews/`:** Detailed, actionable audit reports. These demonstrate how to explain the *why* behind the bug and provide the exact safe code replacement.

## Why this exists?
In AI evaluation platforms (like Mercor or Outlier), an evaluator must provide consistent, objective feedback. A subjective opinion ("this looks bad") is useless. A structured review ("Line 15 uses an f-string for SQL, which violates CWE-89. Fix: use parameterized queries") is what trains the next generation of models.

## How to use it
1. Validate that all artifacts are present and the examples are genuinely vulnerable:
   .\verify.ps1
2. Open `REVIEW_RUBRIC.md` to understand the evaluation mindset.
3. Read the vulnerable code in `bad_code_examples/` and compare it against the solutions in `my_reviews/`.

## Honest Limitations
- This is a static playbook of 2 examples. A full evaluation suite would require hundreds of examples spanning multiple languages (Python, Go, TS).
- It focuses heavily on Backend/Fintech vulnerabilities. For a Frontend/React evaluation, the rubric would need to include XSS and State Management.

## Relevance for AI Training
This playbook proves the ability to think like a Code Reviewer. It demonstrates the exact methodology needed to identify AI hallucinations, evaluate code quality, and provide structured feedback to improve model alignment.
